## TDesc snapshots

`tdesc refresh` imports local `.tdesc` files into a JSON index, manifest, and hash-addressed declaration shards. It records the caller-supplied game version and source label, per-file byte counts and SHA-256 digests, source locations, class/module identities, field attributes, child nodes, and XML line numbers. The index and snapshot have SHA-256 digests. Repeating an import with identical content reuses the existing snapshot. Different content at the same output path is rejected; choose a new path for a new schema snapshot. Raw `.tdesc` files are not copied.

The importer accepts XML rooted at `TuningRoot` with direct `Instance` or `Module` definitions and skips version-history metadata. It blocks DTDs, rejects duplicate class/module identities and non-whitespace text nodes, and limits file count, file size, total input size, and nesting. The game version and source label are caller claims. `tdesc inspect` verifies all declaration shard digests.

Standalone `tuning validate` accepts an optional all-or-none pin: `--snapshot`, `--game-version`, and `--snapshot-sha256`. It checks supported scalar, list, tuple, mapping, and variant shapes against an exact Instance identity. Known schema violations block tuning build/import and project build. Unknown fields and unsupported schema types stay warnings; enums and reference targets are not resolved, absent required fields are not checked, and the version string remains caller-supplied. Project format 2 can opt in using a project-contained `tuningSchema` snapshot path and the same version/digest pin; format 1 retains its prior behavior. Binary tuning remains unverified when a project opts in. Run `pwsh -NoProfile -File scripts/verify-tdesc-snapshot.ps1` for importer integrity and `pwsh -NoProfile -File scripts/verify-tdesc-semantic-validation.ps1` for real-schema semantic and gating checks.

Project validation requires `bytes` for STBL, SimData, PNGImage, DSTImage, LRLE, fixture-backed DXT5 RLE2/RLES, and recognized TS4 translucent JPEG resources. It reports `invalid_resource_encoding` at the resource source path when one of those types is declared as `utf8`. Recognized tuning XML remains UTF-8 validated. For CombinedTuning roots, validation also checks its internal shared-table indexes. Tuning bytes and resources without a typed validator remain opaque. An isolated decode of one real binary CombinedTuning resource produced a packed XML model with 9,765,191 rows and a 1.285 GB peak working set, so project validation does not invoke that eager decoder.

CASP package commands are `casp inspect --package <package> --tgi <type:group:instance>` and `casp rename --package <package> --tgi <type:group:instance> --name <new-name> --output <package>`. They do not change project validation's current opaque-resource behavior. Run `pwsh -NoProfile -File scripts/verify-casp-cli.ps1` to repeat the local v52 fixture check; it writes and removes its temporary packages outside the repository.

For RLE2 and RLES, do not route resources to `GetDdsAsPngAsync` based only on `ResourceFileType.DirectDrawSurface`. The installed LlamaLogic version exposes that metadata but failed to decode actual game payloads. S4MT parses the observed DXT5 layout and decodes RLE2 and RLES blocks independently. Both writers emit opcode-1 blocks and use a generated full mip chain. RLES build/import consume a mip-0 directory bundle with `color.png`, `mask.png`, and `manifest.json`; export can select another mip. The RLE verifiers build standard DDS oracles separately and ask FFmpeg to decode color; RLES mask pixels are expanded independently from its commands and sixth stream. FFmpeg is a verification-time dependency, not a runtime or codec dependency.

The pinned fixture manifest at `scripts/rle-dxt5-fixtures.json` contains resource identifiers and SHA-256 digests only; it does not contain game payloads. Run `pwsh -NoProfile -File scripts/verify-rle-structural-validation.ps1` to re-export and validate all 40 fixture payloads against the installed game package. Run `pwsh -NoProfile -File scripts/verify-rle2-writer.ps1` to rebuild a gradient image, check every generated mip with FFmpeg, test uniform-alpha edge cases, and verify package import preservation. Run `pwsh -NoProfile -File scripts/verify-rles-export.ps1` to compare paired export planes from three real fixtures against the independent FFmpeg DDS and mask oracles. Run `pwsh -NoProfile -File scripts/verify-rles-writer.ps1` to build and import from a real paired export bundle, compare all generated mips against independent color and mask oracles, and check package preservation and malformed inputs.

The independent LRLE implementation uses format information from the [converter published by CmarNYC and tau534](https://modthesims.info/showthread.php?t=650929), who permit reuse with credit. It uses ImageSharp for PNG data and does not link the converter's WinForms or `System.Drawing` code. The LRLE acceptance command is `pwsh -NoProfile -File scripts/verify-lrle-roundtrip.ps1`; it works in a temporary directory and does not launch the game. RLE2 pixel acceptance is `pwsh -NoProfile -File scripts/verify-rle2-export.ps1`; it needs the installed game fixtures and FFmpeg, and also cleans up its temporary files.

## STBL JSON format

```json
{
  "format": 1,
  "tgi": "0x220557DA:0x00000000:0x0034C6AB4A0612D5",
  "locale": "en-US",
  "entries": [
    { "key": "0x00001234", "text": "Localized text" },
    { "key": "0x00001235", "text": "" }
  ]
}
```

Import treats `entries` as the complete target table: omitted keys are deleted, provided keys are set, and empty strings remain valid. Export reports the locale encoded in the high byte of the TGI `instance` through LlamaLogic. Build and import reject a JSON `locale` that does not match the TGI. Older documents can omit `locale`. Unsupported prefixes report `null`.

## Game index layout

The compressed JSONL cache stores one resource provider per line and a trailer record with format version, game version, package count, resource count, and fingerprint. Its cache format is versioned independently from CLI output. The index is rebuilt if package metadata changes or the cache format changes.

Queries retain duplicates across base, pack, and patch packages. Current reports sort patch-tier hints before pack and base hints, but set `precedenceVerified` to `false` and return no effective provider for duplicates.
